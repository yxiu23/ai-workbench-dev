## 二、角度 bug 的真正根因（两个缺陷叠在一起）

你说"生成的图片并没有按设定的角度变化"——查下来是**两处独立缺陷**，各自都能单独让角度失效：

### 缺陷 ① 提示词在 35° 附近**一个字都不生成**

编辑器里算角度提示词的函数是这么写的：

```js
const dv = Math.round(vertical_angle) - 30;   // 相对默认 30° 算差值
if (Math.abs(dv) >= 8) { ... 才生成文字 ... }  // 差值 < 8° 直接跳过
```

- 默认值是 **30°**，所以读数是"相对 30 度偏了多少"
- **差值必须 ≥ 8° 才会吐出任何文字**，否则**提示词是空字符串**
- ⇒ 你设 **30 / 35 / 36 / 37 度**，提示词**完全没有**；设 40 度才只会得到一句模糊的「更俯视约 10°」

**已改成阈值 1°**：现在偏 1 度也会生成文字。

### 缺陷 ② 三轴数值**根本没有结构化下发**

宿主侧原先只把上面那句模糊中文（比如 `「更俯视约 10°」`）拼进 prompt，**水平角/垂直角/缩放三个数字没有以任何形式传给模型**。宿主代码里的原注释写着：

> `速创仅收文本（prompt/urls/mask），params 无下发通道`

⇒ 数字发不出去，模型只能靠一句"更俯视约 10°"自由发挥 ⇒ **出来的图跟设定角度没关系**。

## 三、解法：明了的参考图 + 说死数字

这是你自己提的方向，我照做了：

> 「可能不仅是命令的关系，可以还要搭配明了的参考图，就像面板上的立方体就很直观」

### 做了三件事

**1. 新建 `studio/src/runtime/angleRef.js`（约 200 行，零依赖）**

用 **canvas 2D 手绘**生成一张 **512×512 的 PNG 方位示意图**，内容就是面板上那颗立方体的"平面版"，但**比面板上的更明了**：

- 六面分别标 **前 / 后 / 左 / 右 / 上 / 下**
- **橙色高亮面 = 调整后的相机朝向**（你想让相机在哪一面，哪面就变橙）
- 顶部标题 `TARGET VIEW`，副标 `orange face = camera direction`
- 底部写明三轴实际数值：`H 30°   V 35°   ZOOM 1.0`（及标注 `horizontal · vertical · zoom`）
- 浅灰底 `#f4f5f7`，做了**背面剔除**和**按深度排序**，看起来是颗正经立体

> **为什么是手绘、不是截图？**
> 面板上那颗立方体是 **CSS 3D（DOM 元素）**，浏览器**没法把它直接截成图片**。要截图就得引 `html2canvas` 之类的库（+200KB），**违反你"别再增加体积"的要求**。
> 手绘反而更好：可以加标题、加数值标注、把目标面涂橙——**比截图更"明了"**，这正是你要的效果。
>
> ⚠ 手绘的旋转顺序**严格对齐**面板 CSS（`rotateX(-V) rotateY(H)`），保证**图上方位和你眼睛看到的一致**，不会左右反。

**2. 编辑器把这张图塞进参考图通道**

角度面板点"生成"时，改成**先生成这张立方体图，再把它和参数一起发出**。

好消息：**参考图通道早就存在**，宿主会自动把 `urls[]` 里的图当参考图带给模型（**最多 3 张**）。所以这条改动**不需要新契约、不需要动 Worker**。

**3. 宿主侧把三轴数字"说死"**

宿主拿到角度动作后，除了原有的模糊折句，额外拼进三段硬指令：

- **精确数值**：「把主图的观察视角精确调整到：水平环绕角 **30** 度、垂直俯仰角 **35** 度、缩放 **1**」
- **指认参考图**：「第 2 张图是目标相机方位的示意立方体：橙色面代表调整后的相机朝向，立方体六个面标注了前/后/左/右/上/下，请严格按该方位重绘主图的主体」
- **反污染禁令**：「示意图**仅用于指示方位**，**不要把立方体、边框、文字或任何示意元素画进结果**」

> 说「第 2 张图」是因为：源图固定排第 1 张，参考图从第 2 张起——和上游 `image[]` 的追加顺序一致。

第 3 段禁令很关键——不写清楚，模型真有可能**把立方体本身画进结果图**。

## 六、顺带说清（本轮查日志查出来的，但按你的意思**没动**）

你上一轮说"历史图片不支持就算了"，所以下面两条**我这轮没改**，只是记在这儿备查：

1. **`blob: ERR_FILE_NOT_FOUND` 刷屏** —— 根因是 `r9zcToDataUrl` 读图失败后**把失效的 blob 地址原样退回**，编辑器再去加载它 ⇒ **一次失败产生两条错误**（日志雪崩）。
   修法很小（失败时返回 `null` 而不是退回 `url`）。**要清日志随时说。**
2. **`GET /media/img?url=blob:… 400`** —— 前端不检查地址形态就把 `blob:` 发给 Worker，Worker 回 `only http(s) supported`。
   修法也很小（`blob:` 开头的**本地直接读**，不发 Worker）。

> 这两条与你已放弃的"历史图支持"无关，纯属**日志噪音**。要不要清，你定。

另外记一条**环境事实**：`img.gaze23.work` 实测取 2MB 要 **28.4 秒**，而 `r2.dev` 只要 **2.4 秒**——**慢 10 倍**。这给了你正在考虑的「B 方案（挂自定义域）」一个新理由。
