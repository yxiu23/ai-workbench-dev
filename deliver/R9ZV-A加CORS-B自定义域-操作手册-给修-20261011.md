## 二、B 步：给 R2 桶挂自定义域（建议先做 B，再做 A）

### 步骤（对着菜单名点）

1. 打开 Cloudflare 控制台 → 左侧点 **「R2 对象存储」**（R2 object storage）
   - 直达：`https://dash.cloudflare.com/?to=/:account/r2/overview`
2. 在桶列表里点你的桶（存图那个，`AI_BUCKET` 对应的桶）
3. 点 **「设置」**（Settings）
4. 找到 **「自定义域」**（Custom Domains）→ 点 **「添加」**（Add）
5. 输入域名：
   ```
   img.gaze23.work
   ```
   → 点 **「继续」**（Continue）
6. 核对将要写入的 DNS 记录 → 点 **「连接域」**（Connect Domain）
7. 等状态从 **「初始化中」**（Initializing）变成 **「活动」**（Active）
   - 官方说明：需要几分钟；如果一直不变，点桶右侧 **「…」→「重试连接」**（Retry connection）

### B 的验收（30 秒）

复制下面这条到浏览器地址栏（把 `xxx.png` 换成任意一张真的图路径）：

```
https://img.gaze23.work/results/xxx.png
```

- ✅ 出图 ⇒ **B 成了**
- ❌ 404 页 / 打不开 ⇒ 状态还没到「活动」，等几分钟再试

## 三、A 步：给 R2 桶加 CORS 策略

### 步骤（对着菜单名点）

1. 还是 **「R2 对象存储」** → 点你的桶 → **「设置」**（Settings）
2. 找到 **「CORS 策略」**（CORS Policy）→ 点 **「添加 CORS 策略」**（Add CORS policy）
3. 切到 **「JSON」** 标签页
4. 把下面这段**整段粘进去**（`img.gaze23.work` 若你换名字，这里同步改）：

```json
[
  {
    "AllowedOrigins": [
      "https://www.gaze23.work",
      "https://gaze23.work",
      "https://yxiu23.github.io"
    ],
    "AllowedMethods": ["GET", "HEAD"],
    "AllowedHeaders": ["*"],
    "ExposeHeaders": ["Content-Length", "Content-Type", "ETag", "cf-cache-status"],
    "MaxAgeSeconds": 86400
  }
]
```

5. 点 **「保存」**（Save）

### 为什么是这几个值（我按官方字段说明逐个对过）

| 字段 | 值 | 理由 |
|---|---|---|
| `AllowedOrigins` | 三个域名 | **必须写满 scheme://host，不能带路径**（官方明文）。你的站有两个域名 + GitHub 那个，全列上 |
| `AllowedMethods` | `GET`,`HEAD` | 我们**只读图**，不需要 PUT/POST（不给多余权限） |
| `AllowedHeaders` | `*` | 读图不额外发头，写 `*` 最省事且无风险 |
| `ExposeHeaders` | 那几个 | **官方提醒**：JS 想读到 `Content-Length` 这类头，必须列在 `ExposeHeaders` 里，否则拿不到 |
| `MaxAgeSeconds` | `86400` | 预检结果缓存一天；官方说浏览器最多认 2 小时，写大点没坏处 |

### ★★ 最关键的一条「没配错」判断

**官方原文**：「CORS response headers are only returned when the incoming request
**includes an `Origin` header**.」

⇒ **用 `curl` 直接测是看不到 `Access-Control-Allow-Origin` 的**（curl 默认不发 `Origin`），
**这不代表你没配成功**。要看真实效果，必须在**浏览器**里测（见下）。

## 四、A+B 之后的验收（**必须在浏览器里做**）

### 验收 1：确认 CORS 头真的回来了

浏览器打开 `https://www.gaze23.work/ai-workbench-dev` → **F12 → Console** → 粘贴：

```js
// 换成你自己的一个 img.gaze23.work 图地址
const u = "https://img.gaze23.work/results/xxx.png";
fetch(u).then(r => {
  console.log("HTTP", r.status);
  console.log("ACAO:", r.headers.get("access-control-allow-origin"));  // 应不再是 null
  console.log("长度:", r.headers.get("content-length"));
  return r.blob();
}).then(b => console.log("读到字节:", b.size))
  .catch(e => console.log("失败:", e.message));
```

- ✅ `ACAO: https://www.gaze23.work`（或 `*`）+ `读到字节: 2115831` ⇒ **成了**
- ❌ 仍然 `null` / `Failed to fetch` ⇒ 看下面「五、卡住了怎么办」

## 五、卡住了怎么办

| 症状 | 原因 | 处理 |
|---|---|---|
| 加完 CORS，浏览器仍报缺头 | **旧缓存资产不带新头**（官方明文提示） | Cloudflare 控制台 → **「缓存」→「配置」→ 按主机名清缓存**，清 `img.gaze23.work` |
| 自定义域一直「初始化中」 | DNS 未生效 | 点桶 **「…」→「重试连接」**；或**连接域**那步是否点了确认 |
| `img.gaze23.work` 打开是 404 页 | 公共桶**不支持列目录** | **正常现象**，直接访问具体文件路径即可 |
| `AllowedOrigins` 保存报错 | 值里**带了路径**（如 `https://x.com/foo`） | 只能写 `scheme://host`，去掉斜杠和路径 |
| 规则改动没立刻生效 | 官方说**罕见情况下最长 30 秒** | 等 30 秒重试 |

## 七、★ 一个重要发现：这个坑项目**早就知道**，一直在"逐个绕开"而不是根治

我翻产物时找到三处"历史绕行"，都指向同一个根因（R2 少一个 CORS 头）：

| 处 | 时间 | 当时怎么绕的 |
|---|---|---|
| `ThumbService` 缩略图 | R76-A | 原实现用 `img.crossOrigin="anonymous"` 读 **r2.dev URL** ⇒ 没 ACAO ⇒ **缩略图从未生效**，列表一直加载原图（1~4 MB/张）。改成**走 blob（同源）** 才修好 |
| `directOf` 直连反解 | R76-B | 注释原话：「**无 CORS 的域**（`*.r2.dev`）解包后直连必失败（**img 能显示但 fetch 抛 Failed to fetch**）⇒ 保持 weserv 代理」 |
| `RelayReadFailed` | R9ZE | 中继读回第一跳 fetch `d.url`（r2.dev）⇒ 必被拦 ⇒ 改成走 Worker 取图路由 |

⇒ **结论**：`r2.dev` 无 CORS 这件事，**前后至少踩了三次**，每次都用"另一条路绕过"。
而你这次报的「送不进编辑器」，是**第四次**，只是这一处**还没被绕**。

**⇒ 做完 A+B 之后，这三个历史绕行都可以"退役回归正路"**：
缩略图不必再走 blob、图不必再走 weserv 代理、读回不必再走 Worker 路由。
（**不急**，属于"可做未做"清单；但 A+B 是它们能退役的前提。）

**这也说明 A+B 是"根治"而不是"再绕一次"** —— 这正是我推荐它的理由。
