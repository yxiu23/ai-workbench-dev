## 二、真凶：一个"根因"，两个"症状"

### 根因：R2 公开域**从来不返回** `Access-Control-Allow-Origin`

实测（`验收/_r9zu_r2cors_probe.py`，可复跑）：

```
GET https://pub-0f64bcd….r2.dev/results/xxx.png
  → 200 OK · Content-Type: image/png · Content-Length: 2115831
  → Access-Control-Allow-Origin: **缺失**
带 Origin: https://www.gaze23.work 再试 → 依然**缺失**
```

### 为什么"以前好好的，现在炸了"—— 这是关键

| 用法 | 需要 CORS 吗 | 结果 |
|---|---|---|
| `<img src="https://pub-….r2.dev/…">`　**显示图片** | ❌ 不需要 | ✅ 一直正常 |
| `fetch("https://pub-….r2.dev/…")`　**读图片字节** | ✅ **需要** | ❌ **浏览器直接拦死** |

**同一个 URL，显示没问题、读取必失败。** 所以历史记录里的缩略图能看到，
但一旦你要「把它送进编辑器 / 当参考图 / 当源图」，程序必须**读到字节** ⇒ 立刻撞墙。

**这不是"新坏了"，是"以前那条路没被走到"。**

### 症状 A：`blocked by CORS policy`（你截图里的第一批）

全部来自**读 R2 直链**的地方。前端其实**已经有三处**改走 Worker 代理了（R9W/R9ZE 做过），
但**漏了这几处**：

| 位置（源码行） | 场景 | 现状 |
|---|---|---|
| `blobUrlToDataURL` | **画布图像 → dataURL**（送编辑器/参考图的正路） | ❌ 裸 fetch |
| `_preloadResult` ① ~18129 | 原图预览秒开缓存 | ❌ 裸 fetch |
| `_preloadResult` ② ~18268 | 结果转存 R2 | ❌ 裸 fetch |
| `stageImage` ~13478 | **抠图前把源图送阿里** | ❌ 裸 fetch |
| `_w5vToDataUrl` 三处 ~25025/25214/25235 | 视频参考素材转存 | ❌ 裸 fetch |

对照：`13347`（R9ZE 修的）**已经是"首选 `/media/img`、两条老路兜底"** —— 写法我照抄即可。

### 症状 B：`blob: ERR_FILE_NOT_FOUND`（你截图里的第二批）

**这是症状 A 的直接后果，不是独立 bug**：
读 R2 失败 ⇒ 走"转 dataURL 降级"分支 ⇒ 生成 `blob:` URL ⇒ 但字节从来没拿到（`size=0`）
⇒ 那个 blob URL 指向空内容 ⇒ 一挂就 `ERR_FILE_NOT_FOUND`。

⚠ 顺带印证：这正是我记忆里 R9ZO 那条「转 dataURL 降级**静默无痕**」——降级失败了却不出声，
所以你看到的是一堆"莫名其妙的 blob 报错"，而不是"R2 读取失败"。

## 三、修法：**你不用做任何事**（这是重点）

Worker **早就有** `GET /media/img?url=<encoded>` 服务端取图口（R9W 建，线上 `caps.readProxy:true`）。
**服务端 fetch 不受 CORS 约束**。我实测过：

```
curl -H "Authorization: Bearer <token>" \
  "https://media.gaze23.work/media/img?url=<encoded R2 url>"
→ HTTP 200
→ Content-Type: image/png
→ Content-Length: 2115831     ← 与 R2 原件字节数完全一致
→ Access-Control-Allow-Origin: *   ← ★ 就是缺这个头
```

★ 而且 Worker 对**自家 R2** 走的是「按 key 从 `AI_BUCKET` 直读」——**不出网、比 R2 直链还快**。

**所以修法 = 把那 5 处（7 个 fetch 点）改成与 `13347` 同款写法**：
```
首选 → Worker 代理（带 ACAO、不出网）
兜底 → 原 R2 直链（不改、不删，某些环境仍有意义）
```
⇒ 改完立刻好，**且完全不需要你加 CORS 规则**。
