# 修 · R2 加 CORS 规则（中文操作步骤）

> **为什么必须做**：图片生成成功后存在 R2，但前端**读不出来** —— 浏览器报
> `No 'Access-Control-Allow-Origin' header is present`。
> 你看到的「失败/不显示」，一半是这个原因，**不是生成失败**。

---

## 一、操作（Cloudflare 控制台，约 2 分钟）

1. 打开 https://dash.cloudflare.com/ ，登录
2. 左侧菜单找 **「R2 对象存储」**（英文界面是 **R2 Object Storage**）
3. 点进你的桶 —— 名字里带 **`ai-media`** 或对应 `pub-0f64bcd69f464228b22d20964f000919` 那个桶
   - ⚠ 别点错，就是**放生成图片**的那个桶
4. 进桶后，上方标签页找到 **「设置」**（Settings）
5. 往下滚，找到 **「CORS 策略」**（CORS Policy）→ 点 **「添加 CORS 策略」**/**「编辑」**
6. 把下面这段**整段原样粘贴**进去：

```json
[
  {
    "AllowedOrigins": [
      "https://www.gaze23.work",
      "https://yxiu23.github.io"
    ],
    "AllowedMethods": ["GET", "HEAD"],
    "AllowedHeaders": ["*"],
    "ExposeHeaders": ["Content-Type", "Content-Length", "ETag"],
    "MaxAgeSeconds": 3600
  }
]
```

7. 点 **「保存」**

---

## 二、验证（贴完立刻验）

浏览器直接打开这个地址，看有没有报错：

```
https://pub-0f64bcd69f464228b22d20964f000919.r2.dev/
```

或者告诉我，我用下面这条命令复验（**看有没有 `access-control-allow-origin` 这一行**）：

```bash
curl -sI -H "Origin: https://www.gaze23.work" \
  "https://pub-0f64bcd69f464228b22d20964f000919.r2.dev/" | grep -i access-control
```

**出现 `access-control-allow-origin: https://www.gaze23.work` = 成功。**

---

## 三、注意事项

- **一个桶只能有一条 CORS 策略**。如果桶里**已经有一条**，不要新建、要**编辑现有那条**，把 `AllowedOrigins` 改成上面两个（或直接在原数组里**追加**这两个）。
- 如果你在桶里看到已有策略且**不确定该不该覆盖**，先把原有内容**截图或复制下来发我**，我看完告诉你改哪里。
- 改完**立即生效**，不用重新部署任何代码。
- 这一步**只影响跨域读取**，不影响上传、不影响已有图片。
